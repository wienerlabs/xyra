# Xyra UI translations

This folder holds the **build-time** English->localized-language translation layer for Xyra's interface. Zed has no built-in i18n (UI strings are string literals baked into the Rust source), so translation is done by source-string replacement, the same way the brand patches work — it is an extension of Xyra's existing `build/rebrand-strings.py` pipeline.

Currently supported: **Turkish (`tr`)**.

## Files

| File | What | How it is produced |
|---|---|---|
| `candidates.json` | Pool of translatable UI string candidates; key = the **branded** source literal (e.g. `"Welcome to Xyra"`), value = its locations (`crates/...:line`). | Generated by `build/extract-ui-strings.py`. Do not edit by hand. |
| `glossary.tr.json` | `keep`: exact strings that must never change, even if a translation exists (brand, product, language and protocol names, plus the brand-gate string). | By hand. |
| `tr.json` | English->Turkish translations; keys match `candidates.json` exactly. | AI draft + glossary + native review. |

## How the pipeline works

```
1. EXTRACT   build/extract-ui-strings.py   -> candidates.json   (from the branded source)
2. TRANSLATE fill in tr.json               -> AI draft + glossary + native review
3. APPLY     build/translate-strings.py    -> inside patch-brand.sh, after the rebrand
4. BUILD     script/bundle-mac             -> localized Xyra.app
```

`patch-brand.sh` calls `translate-strings.py` **after** the brand rebrand and all UI patches (so the keys are branded English). It only runs when `XYRA_LANG` is set and not `en` — the English build is untouched.

## Safety rules (why this is not a blind pass)

- **Location-restricted translation:** `translate-strings.py` translates a string only at a UI location recorded for that string in `candidates.json` (`file:line`). This prevents short words like `"Name"`/`"Push"` from being translated in a non-UI context (serde value, JSON key, action id).
- **keep list:** strings in `glossary.tr.json` -> `keep` never change. The `"Welcome to Xyra"` string that the brand verification gates (`release.yml`, `publish-release.sh`) look for is listed there, so it stays English and CI does not break.
- **Placeholder protection:** `{...}` placeholders in the source must be preserved verbatim in the translation; if they are not, that translation is skipped and reported.
- **Idempotent:** only exact-matching English literals change, so re-running is safe.
- **Context guards:** `translate-strings.py` additionally refuses to translate literals in Rust contexts where a change would break compilation or runtime — serde/schema/macro/attribute/env, `build.rs`, `migrator/`, raw strings, match-arm patterns, JSON/map keys, `.get()/.contains()/.starts_with()/.header()` arguments and keymap dispatch contexts.

## Adding new translations (next wave)

1. Find the key to translate in `candidates.json` (copy it verbatim — mind differences like `…` ellipsis vs `...`).
2. Add a natural Turkish value, consistent with the glossary, to `tr.json` -> `translations`.
3. Verify with a dry run:
   ```bash
   python3 build/translate-strings.py ~/.cache/xyra/zed-src --lang tr
   ```
   Expect `unapplied 0` and `placeholder-skipped 0`. (The source must already have `patch-brand.sh` applied — see regeneration below.)

## Regenerating candidates.json (when the Zed version changes)

`candidates.json` is generated from the **branded** source; order matters:

```bash
git -C ~/.cache/xyra/zed-src reset --hard && git -C ~/.cache/xyra/zed-src clean -fdq
./build/patch-brand.sh ~/.cache/xyra/zed-src
python3 build/extract-ui-strings.py ~/.cache/xyra/zed-src
```

## Known limits

- **Extraction is conservative:** it only catches common UI call patterns (`Label::new`, `.tooltip`, menu actions, struct fields, filtered bare literals). To widen coverage, add patterns to `UI_PATTERNS` in `build/extract-ui-strings.py`; that is the work of later waves.
- **Version maintenance:** on every Zed upgrade, `candidates.json` is regenerated; new or changed strings stay English until added to `tr.json`.
- **Dynamic action names:** command-palette/keymap names generated at runtime cannot be covered by a version-stable patch (a Zed-wide limit).
